# Execution policies

The [`policies/`](../audio_edit/policies/) package separates policy selection from audio-tool execution. Its stage interfaces preserve an explicit strategy order. Strategy modules contain the evidence checks, permitted changes, and sound-specific conditions.

| Stage interface | Responsibility |
|---|---|
| [`removal.run_removal`](../audio_edit/policies/removal/__init__.py) | Coordinate direct removal, retained-source paths, and residual corrections. |
| [`material.clean_generated_material`](../audio_edit/policies/material/__init__.py) | Check generated replacement assets for old instruments, unwanted singing, or incompatible timbre. |
| [`rendering.prepare_material`](../audio_edit/policies/rendering/__init__.py) · `material_renderer` | Select eligible structure-preserving rendering and the independent-piano generation adapter. |

Each stage exports an ordered `POLICIES` tuple. The frozen [`PolicySpec`](../audio_edit/policies/core.py) describes a policy's identifier, stage, condition, evidence, action, and budget. The package's `catalog()` lists this metadata without running a strategy. `record_policy()` appends decisions to `params.policy_trace`; detailed strategy audits remain under their existing `params` keys.

Metadata describes the rules; stage code controls invocation and strategies enforce their applicability checks. Some strategies name particular sound classes or require literal phrases in a plan. These conditions remain explicit below and in their implementations.

Limits apply to one branch invocation or material asset unless stated otherwise. A request may enter more than one branch, so these are not a single global correction budget. Application-level calls also differ from transport retries inside model clients.

| Stage | Trigger and permitted action | Limit and evidence | Implementation |
|---|---|---|---|
| Collaborative planning | The selected operation has unresolved target, timing, identity, or preservation dependencies. The planner can request listening or a supported measurement. | At most 2 Qwen listens and 2 tool requests across 4 action turns; source extraction is available at most once. Exhausted essential dependencies remain unresolved. | [`listen_for_edit`](../audio_edit/analyzers/edit_listening.py) |
| Whole-file laughter removal | An unselected, whole-file removal uses the generic query `laughter`, `laughing`, or `human laughter`. First original and residual descriptions must both explicitly support remaining laughter before the query can be refined. | One first description per audio hash, one first binding decision per request key, and at most 1 revised SAM execution. Persistent claims prevent repeating an unanswered observation or decision. | [`vocal_activity_query`](../audio_edit/policies/removal/vocal_activity_query.py) |
| Music within a multi-source removal | A supported span plan selects multiple distinct sound types, including exactly one `music` or `background music` interval. The first residual must confirm that selected music remains. | At most 1 new residual description and 1 continuation separation on the selected music interval. The original event selection and other intervals remain fixed. | [`residual_completion`](../audio_edit/policies/removal/residual_completion.py) |
| Singing in generated instrumental material | A replacement requests a supported instrument or accompaniment, with no requested vocals. The first generated-asset description must positively identify unwanted singing. | One first description per asset hash and one decision for this branch; if eligible, 1 SAM cleanup removes singing from the generated asset. The original residual is unchanged. | [`instrumental_material`](../audio_edit/policies/material/instrumental_material.py) |
| Replaced piano in generated material | The old source is specifically piano, the requested new source is one supported non-piano instrument, and the first asset description supports both. Ensembles are excluded. | One first description per asset hash and one decision for this branch; if eligible, 1 SAM cleanup removes piano from the new asset. The first description can be shared with the singing check. | [`generated_old_instrument`](../audio_edit/policies/material/generated_old_instrument.py) |
| Optional instrument rendering | Supported isolated-instrument replacements require preservation of musical structure and satisfy the renderer's plan and observation checks. Program selection includes explicit piano, harp, violin, and humming cases. | One Basic Pitch transcription and one SoundFont render per eligible invocation; missing resources or renderer failure retain the existing generator route. This is an alternate rendering branch. | [`music_timbre`](../audio_edit/policies/rendering/music_timbre.py), [`run_music_timbre.py`](../audio_edit/tools/run_music_timbre.py) |
| Source-relative volume level | For `gain_profile="level"`, the initial separated target is more than 30 dB below the original mixture in the target scope. | At most 2 additional query variants per target: a simple singular form and `The sound of …`, skipping duplicates and the original query. Select the finite candidate with the largest in-scope RMS. This heuristic does not verify source identity. | [`run_source_volume`](../audio_edit/tools/run_sam_audio.py) |
| Generation or planning call failure | A wrapped tool call raises an error, or its audio fails finite/nonempty validation. | Default 2 total attempts for the same call. These are error retries, not a quality-based search over successful outputs. | [`bounded_call`](../audio_edit/utils/bounded_tools.py), [`AddSoundRunner`](../audio_edit/runners/add_sound_runner.py), [`add_sound.py`](../audio_edit/user_scripts/add_sound.py) |
| Basic execution route | The primary route cannot finish. The basic planner receives the original instruction and duration, without the failed route's listening evidence. | One planning request with API retries disabled, producing 1–4 actions. Each action is attempted once; partial progress and delivery errors are retained. | [`first_plan`, `render`, `recover`](../audio_edit/tools/basic_execution.py) |

Each SAM separation uses the model's configured eight-candidate ranking internally; this is distinct from the branch-level call limits above. Automatic time-span prediction is used only when text separation has no explicit anchors. See [`_separate`](../audio_edit/tools/run_sam_audio.py).

The report preserves branch audits under `params`, along with `execution_path`, `fallback_used`, `execution_status`, and `execution_error`. If a replacement substep fails, its policy trace and `primary_execution_snapshot` remain available during basic recovery. A delivered or changed waveform does not by itself establish perceptual correctness. An otherwise completed operation with unchanged output is reported as `no_op`; this and execution failures return a nonzero exit status.
